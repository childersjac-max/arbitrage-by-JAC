
### B) Dashboard API — after `python web_app.py`

- `GET /api/status?day=today` → JSON with `opportunities[]` built from `UnifiedRecord` rows with `arbitrage != null`
- Each opportunity (see `dashboard_service._opportunity_from_record`):

```json
{
  "id": "event_id",
  "event_name": "Away @ Home",
  "sport_key": "basketball_nba",
  "market_type": "h2h | spreads | totals | ...",
  "commence_time": "ISO-8601 | null",
  "yield_pct": 2.0,
  "implied_sum": 0.98,
  "legs": [
    { "source": "draftkings", "outcome": "Team A", "price": 2.05, "stake_weight": 0.48 }
  ],
  "arb_method": "math | llm",
  "sources_used": []
}
```

**Note:** Today’s pipeline often returns **0 opportunities** (no arb). UI must handle that. Player-prop **ladders** only appear when `market_type` and `sources` actually contain them — do not fabricate 10-deep ladders.

### C) Stake math (client-side, must implement in JS)

Given total bankroll `B` (from top slider, default `1000`) and legs with `stake_weight` and **decimal** `price`:

```
w_sum = sum(leg.stake_weight)
stake_i = B * (leg.stake_weight / w_sum)
payout_i = stake_i * leg.price   // equal payout for valid 2-way arb
profit = payout_i - B
roi_pct = (profit / B) * 100
```

Display ROI badge: `+$${profit.toFixed(2)} • ${roi_pct.toFixed(1)}% ROI`  
Use `yield_pct` from API when present; recalc when user edits per-leg stake inputs.

American odds display (optional): convert decimal `d` for UI only; keep math in decimal.
